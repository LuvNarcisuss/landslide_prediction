## 一、整体设计框架

### V2 核心设计思想：二阶段分离（易发性 vs 风险）

| 层面 | 处理方式 | 意义 |
|------|---------|------|
| **易发性特征** (`SUSCEPTIBILITY_FEATURES`) | 参与分类模型训练 | 仅包含地形、降雨、植被、坐标、土地利用 → 反映"哪里可能滑坡" |
| **暴露特征** (`EXPOSURE_FEATURES`) | 不参与分类，仅存 `extra` 字典 | 用于事后风险分析 → 反映"滑坡会威胁多少人/财产" |

### 特征列表

```python
SUSCEPTIBILITY_FEATURES = [
    # 地形因子 (4)
    'elevation', 'aspect', 'tpi', 'distance_to_river',
    # 降雨因子 (4)
    'rain_3d', 'rain_7d', 'rain_30d', 'api',
    # 植被因子 (2)
    'ndvi', 'ndwi',
    # 坐标 (2)
    'lon', 'lat',
    # 土地利用
    'landuse',
    # 新增衍生特征 (7)
    'rain_ratio_3d_30d', 'rain_ratio_7d_30d', 'rain_intensity',
    'valley_risk', 'elev_rain', 'aspect_rain', 'ndvi_elev',
    'log_dist_river',
]

EXPOSURE_FEATURES = [
    'threatened_people', 'threatened_households', 'threatened_property',
    'exposure_index',
]
```

### 评价

**✅ 合理**。这是滑坡易发性评价的标准做法。暴露特征（人口、财产）如果加入分类模型会成为"捷径特征"（模型可能学到"有人的地方才滑坡"这种因果倒置的规律），分离后模型学的是真实的地质-气象规律。

## 二、7 个新增衍生特征逐条分析

---

### 特征 1 & 2：`rain_ratio_3d_30d` 和 `rain_ratio_7d_30d`

**实现公式：**

```python
df['rain_ratio_3d_30d'] = df['rain_3d'] / (df['rain_30d'] + 1e-8)
df['rain_ratio_7d_30d'] = df['rain_7d'] / (df['rain_30d'] + 1e-8)
```

| 维度 | 分析 |
|------|------|
| **实现** | 短期累积降雨量 / 长期累积降雨量，加 `eps=1e-8` 防除零 |
| **物理意义** | 反映降雨的**集中程度**而非绝对量。比值高 → 短期降雨集中在近期，土壤含水量快速上升 |
| **是否符合事实** | ✅ 合理。滑坡触发通常与"短期强降雨"而非"长期总雨量"关系更大。同样30天总雨量100mm，如果3天内下了80mm（ratio=0.8）比分散下（ratio=0.2）更易触发滑坡 |
| **设置合理性** | 分母用 `rain_30d` 作为基线合理。但注意 `eps` 只防除零不防溢出——当 `rain_30d` 接近0而 `rain_3d` 很大时比值会异常大，好在 `StandardScaler` 后续会标准化 |

---

### 特征 3：`rain_intensity`

**实现公式：**

```python
df['rain_intensity'] = df['rain_3d'] / (df['rain_7d'] + 1e-8)
```

| 维度 | 分析 |
|------|------|
| **物理意义** | 降雨强度指数。越接近1.0说明3天内的雨几乎全是最近3天下完的（短时强降雨） |
| **是否符合事实** | ✅ 很合理。地质学中"降雨强度-历时阈值"（IDF曲线）本身就是滑坡预警的核心指标 |
| **与 V1 对比** | 完全一致，是经过V1验证的特征 ✅ |
| **潜在问题** | 当 `rain_7d` 很小且 `rain_3d` 也不大时，比值可能虚高（如 rain_3d=2mm, rain_7d=3mm → ratio=0.67, 但实际雨量很小） |

---

### 特征 4：`valley_risk`

**实现公式：**

```python
df['valley_risk'] = np.maximum(0, -df['tpi']) / (df['distance_to_river'] + 1)
```

| 维度 | 分析 |
|------|------|
| **实现细节** | `-tpi` 取负值 → TPI负值代表谷地；`max(0, -tpi)` 只取谷地正值；除以 `distance_to_river + 1` 做距离衰减 |
| **物理意义** | 谷地（低洼汇水区）且靠近河流的区域，土壤含水量高、坡脚冲刷，滑坡易发 |
| **是否符合事实** | ✅ **此特征是地质合理性最高的特征之一**。TPI负值（谷地）+ 距河近 → 典型的滑坡易发组合。但需注意 `+1` 的单位问题——`distance_to_river` 的单位是米，`+1` 的影响很小，可能需要用 `distance_to_river + 100` 或改成 `np.log1p(distance_to_river)` |
| **设置合理性** | ⚠️ **存在一个隐患**：当样本恰好在河道上（tpi极负 + distance_to_river接近0）时该值会极大，但河道不应该是滑坡点而可能是水体 → 后续可能淹没关系 |

---

### 特征 5：`elev_rain`

**实现公式：**

```python
df['elev_rain'] = df['elevation'] * np.log1p(np.maximum(df['rain_3d'], 0))
```

| 维度 | 分析 |
|------|------|
| **物理意义** | 高海拔 + 强降雨 → 交互效应。高海拔区温度低蒸发弱，相同降雨量下土壤含水量更高 |
| **是否符合事实** | ✅ 在四川汶川地区有实际意义——海拔2500m以上的降雨效应与低海拔不同。但需注意四川地区降雨随海拔先增后减的"迎风坡效应"，此特征仅捕捉线性交互 |
| **与 V1 对比** | V1 使用的是相同的实现，有 `np.maximum(..., 0)` 保护 ✅ |

---

### 特征 6：`aspect_rain`

**实现公式：**

```python
df['aspect_rain'] = np.cos(np.radians(df['aspect'])) * df['rain_3d']
```

| 维度 | 分析 |
|------|------|
| **实现** | `cos(弧度(aspect))`：坡向0°（北）→ cos=1；180°（南）→ cos=-1；90°/270°（东/西）→ cos≈0 |
| **物理意义** | 北向坡（cos大）+ 强降雨 = 光照少蒸发弱，土壤更湿润 → 滑坡易发。南向坡（cos负）干燥 |
| **是否符合事实** | ⚠️ **部分合理但北半球有反直觉之处**：在北半球中高纬度，**南向坡（阳坡）** 接受太阳辐射多，融雪更快、冻融作用更强，可能导致更频繁的浅层滑坡。而北向坡（阴坡）土壤湿度确实更高但不如南向坡冻融循环剧烈。此特征对四川汶川（北纬31°左右）的效果需要实际验证 |
| **建议** | 此特征的方向性（cos(0)=1给北坡最高值）隐含了"北坡更湿→更容易滑坡"的假设，这在部分地区成立但不是普适规律。更好的做法是用 `abs(sin(aspect))` 表示坡向的"陡峭程度"而非方向，或者保留让模型自行学习 |

---

### 特征 7：`ndvi_elev`

**实现公式：**

```python
df['ndvi_elev'] = df['ndvi'] * df['elevation'] / 1000.0
```

| 维度 | 分析 |
|------|------|
| **实现** | NDVI（植被覆盖度）× 高程 / 1000，除1000是为了让量级与其他特征匹配 |
| **物理意义** | 高海拔 + 高植被覆盖 → 交互效应。高海拔区植被根系较浅，对表层土加固有限，覆盖度高反而增加坡面荷载 |
| **是否符合事实** | ✅ 合理。但更直接的做法是用 `ndvi / elevation`（植被覆盖率 vs 高程梯度），因为滑坡往往发生在"高处植被好但根部抓不住深层土"的区域 |
| **与 V1 对比** | V1 用的是 `ndvi_rain = ndvi × log1p(rain_3d)`，V2 换成了 `ndvi_elev`。**这个替换有意义**——V1的 `ndvi × rain` 和 `elev_rain` 相关性太高（都包含了 rain_3d 项），V2用 `ndvi_elev` 引入了新的信息维度 |

---

### 特征 8：`log_dist_river`

**实现公式：**

```python
df['log_dist_river'] = np.log1p(np.maximum(df['distance_to_river'], 0))
```

| 维度 | 分析 |
|------|------|
| **实现** | `np.log1p(max(distance_to_river, 0))`，既处理负值又压缩长尾 |
| **物理意义** | 距河距离取对数后，原始尺度上的"100m vs 1000m"差异显著，而"5100m vs 6000m"差异不重要 |
| **是否符合事实** | ✅ 标准做法，几乎所有的地质灾害建模都会对距离变量做对数变换 |
| **设置合理性** | 注意原始 `distance_to_river` 已经在特征列表中保留了，新增 `log_dist_river` 相当于同时保留了线性和对数两个视角，模型会自己学习哪种更有用 |

## 三、与 V1 (preprocess.py) 的关键差异对比

| 特征 | V1 | V2 | 评价 |
|------|----|----|------|
| `ndvi_rain` | ✅ 有 | ❌ 无 | V2 换成了 `ndvi_elev`，减少了特征共线性 ✅ |
| `ndwi_ndvi_diff` | ✅ 有 | ❌ 无 | 移除合理——NDWI与NDVI高度相关，增加维度有限 |
| `tpi_elev` | ✅ 有 | ❌ 无 | 与 `elev_rain` 有重叠，移除合理 |
| `geo_cluster` (KMeans×10) | ✅ 有 | ❌ 无 | **移除是合理的选择**——KMeans聚类结果作为特征会让模型过度依赖空间"块状"划分，且每次运行不完全确定 |
| `missing indicators` (4个) | ✅ 有 | ❌ 无 | V2 放在 `data_cleaning.py` 的 `add_missing_flags()` 中，但**未纳入特征列表** ✅（缺失信息已通过插补解决） |
| `has_rain/earthquake/human` | ✅ 有 | ❌ 无 | **重大改进**——诱发因素是灾害**成因**而非地形"易发性"，加入后会导致训练/推理不一致 |

### 总体评价

V2 的特征设计比 V1 **更干净、更符合"易发性评价"的学术规范**。

## 四、标准化策略分析

```python
onehot_cols = [c for c in X.columns if c.startswith('lu_')]
geo_cols = ['lon', 'lat']
skip_cols = onehot_cols + geo_cols         # 跳过 One-hot 和经纬度
scale_cols = [c for c in X.columns if c not in skip_cols]  # 其余标准化
```

| 判断 | 理由 |
|------|------|
| ✅ **One-hot 不标准化** | 二值变量标准化后失去"整数0/1"的稀疏性，模型解释性变差 |
| ✅ **经纬度不标准化** | 经纬度反映绝对位置，标准化后地理意义丢失。且 `lon`/`lat` 是通过 `BallTree` 的地理距离做缓冲区的基础 |
| ⚠️ **`landuse` 被标准化了** | `landuse` 是整数编码的分类变量（1,2,3...），标准化后变成浮点数——可能不合理。更好的做法是用 One-hot 或 OrdinalEncoder。考虑到 `landuse` 已经有 `landuse_type` 的 One-hot 编码，`landuse` 本身就可以考虑从特征列表中移除 |

## 五、潜在问题与改进建议

### 问题 1：交互特征间的多重共线性

```python
elev_rain = elevation × rain_3d               # 与 rain_3d 部分线性相关
aspect_rain = cos(aspect) × rain_3d            # 同样包含 rain_3d
```

- 如果后续模型是**树模型**（RF/XGBoost/LightGBM/CatBoost）→ **不敏感**
- 如果是**逻辑回归/SVM** → **需要检查 VIF（方差膨胀因子）**

### 问题 2：`landuse` 编码方式不统一

```
SUSCEPTIBILITY_FEATURES 里包含 'landuse'（整数编码）
build_susceptibility_features() 里对 'landuse_type' 做 One-hot
StandardScaler 会对 'landuse' 标准化
```

**建议**：将 `'landuse'` 从 `SUSCEPTIBILITY_FEATURES` 中移除，仅保留 One-hot 编码。

### 问题 3：`rain_ratio` 系列特征对零值敏感

当 `rain_30d ≈ 0` 时：

```python
rain_ratio_3d_30d = rain_3d / 1e-8  # → 巨大值
```

虽然 Scaler 会处理，但如果训练集和测试集中此类样本分布不均，会导致预测不稳定。

**建议**：对比值特征加一个 `np.clip(..., 0, 5)` 的上限裁剪。

### 问题 4：`aspect_rain` 的方向性假设

在北纬31°的四川汶川地区，南向坡（阳坡）的**冻融作用**可能比北向坡（阴坡）的**高湿度**对滑坡的贡献更大。当前 `cos(aspect)` 给北坡最高值、南坡负值的编码方向可能与实际相反。

**建议**：实测后决定保留、取绝对值、或改用 `sin` 编码。

### 问题 5：缺少坡度（slope）特征

滑坡易发性分析中，**坡度(slope)** 通常是最重要的单一因子之一。现有特征中 `tpi` 和 `aspect` 只能部分反映地形起伏。

**建议**：如果原始 DEM 数据允许，计算坡度将是最大的单点提升。

## 六、总体评分与建议优先级

| 特征 | 地质合理性 | 实用价值 | 建议 |
|------|-----------|---------|------|
| `valley_risk` | ⭐⭐⭐⭐⭐ | 高 | ✅ 保留 |
| `rain_ratio_3d_30d` / `rain_ratio_7d_30d` | ⭐⭐⭐⭐⭐ | 高 | ✅ 保留 |
| `rain_intensity` | ⭐⭐⭐⭐⭐ | 高 | ✅ 保留 |
| `log_dist_river` | ⭐⭐⭐⭐⭐ | 高 | ✅ 保留 |
| `elev_rain` | ⭐⭐⭐⭐ | 中高 | ✅ 保留 |
| `ndvi_elev` | ⭐⭐⭐⭐ | 中 | ✅ 保留 |
| `aspect_rain` | ⭐⭐⭐ | 中 | ⚠️ 实测验证方向假设 |
| `landuse`（整数编码） | ⭐⭐ | 低 | ❌ 移除（已有 One-hot） |

### 总评

V2 的特征工程**质量很高**——比 V1 (`preprocess.py`) 在学术规范性和地质合理性上都有明显提升。25~35 个特征（含 One-hot）在滑坡易发性研究中属于合理规模（通常 15~40 个特征），既不会过拟合也不会欠拟合。

核心改进点：
1. ✅ **纯化"易发性"概念**——暴露特征分离，不参与分类
2. ✅ **避免特征泄漏**——诱发因素（has_rain/earthquake/human）不加入分类特征
3. ✅ **移除不稳定特征**——去掉 KMeans 地理聚类
4. ✅ **减少共线性**——用 `ndvi_elev` 替换 `ndvi_rain`

后续提升优先级：**坡度(slope) > 降雨比值特征裁剪(Clip) > 统一 landuse 编码**
